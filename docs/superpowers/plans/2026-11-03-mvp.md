# SurveyCoach MVP Implementation Plan

> **For agentic workers:** Use executing-plans task by task; preserve the existing Studio workspace. Approved scope is the six-part researcher workflow in the conversation and the existing survey-coach/reader specs.

**Goal:** Import an actual survey, review it, preserve decisions, work through fixes, re-check changes, and export an honest review summary.

**Architecture:** Reuse the Python engine and existing Studio renderer. Add a local FastAPI service with SQLite for versioned reviews/decisions and background jobs; public Pages remains synthetic-only. Build and test a reader against controlled local surveys before approved real access. Do not claim validation against research leadership until it actually happens.

**Constraints:** No automated real RedJade crawl without satisfied vendor/test-participant safety prerequisites. No final response submission. No real survey material in git/public Pages. No invented approval, no fake AI. Keep files cohesive and generally under 600 lines. Use existing approved Studio visual direction. No new severity/scoring weights without owner decision.

## 1. Trust contracts
- [ ] Add failing regressions for failed-batch readiness, contradictory IDs, target-scoped dedupe/preview, no-op preview, copy-original semantics, and Ask delimiters.
- [ ] Make incomplete AI scoring unable to produce Ready; retain clearly named deferred image checks without presenting them as earned.
- [ ] Reject duplicate verdict/blocker IDs; rejected AI output remains unchecked.
- [ ] Scope rewrite ownership to location; delimiter-wrap all untrusted finding context.
- [ ] Target preview replacements to the finding's page/question, do not register identity swaps, use one unit for must-fix counts, disable suggestion-copy for original picks.
- [ ] Run full suite and offline demo regeneration; commit only reviewed source/tests/synthetic fixtures.

## 2. Persistent review workflow
- [ ] Add SQLite repository for surveys, immutable versions, review JSON, explicit choices/reasons and done states. Stable findings use criterion+location+evidence fingerprints; choices version-scoped.
- [ ] Add FastAPI app factory, loopback-only launcher, bounded request validation, same-origin write protection, snapshot import/list/review/decision/version/packet APIs. Providers injected for tests; real service uses Wibey, never FakeProvider implicitly.
- [ ] Background jobs expose progress and failures; one active review per survey. No completed review on malformed input/model failures.
- [ ] Compare versions conservatively: resolved/still open/new is based on repeated checks of changed source, never copying/checking a box. Unchanged hashes create no new version.

## 3. Connect Studio and work list
- [ ] Add private local entry point for survey import/home/version navigation; public demo unchanged in capabilities.
- [ ] Reuse workspace with API-loaded reviews, grouped copyable fixes, explicit choices, reasons for keeping, saved manual done states, copy all excluding originals.
- [ ] Label copied/manual done/verified resolved separately. Show failed and pending checks clearly. Add Ask interaction using server-only provider.
- [ ] Export escaped self-contained HTML summary with version, source/coverage, unchecked checks, open findings and decisions; never imply automatic approval or RedJade editing.

## 4. Reader and link ingestion
- [ ] Controlled Survey Zoo fixtures cover choices/text/grids, navigation, screenouts, images and final-submit stop.
- [ ] Build bounded Playwright reader with page capture/snapshot extraction, explicit coverage, image-fetch provenance, stop controls and navigation budgets. Validate HTTP destinations and deny local/private networks in production; explicit test-only fixtures separate.
- [ ] Wire link intake/jobs/re-check with prerequisite notices; retain last successful version on failures. Incomplete coverage cannot be called launch ready.
- [ ] Verify with controlled fixtures only; record real-vendor approval/access as an external pilot gate rather than inventing it.

## 5. Acceptance and handoff
- [ ] Full unit/API/browser tests including persistence after reload, actual new review, update/recheck, summary export and partial failures.
- [ ] Responsive/keyboard/axe checks and independent review; fix verified material defects.
- [ ] Update README/roadmap with actual supported features, local test instructions and remaining pilot gates.
- [ ] Start local app in background, verify health, open in browser. Report exact delivered capabilities and any blocked reader/validation steps honestly.

## Execution checkpoint

- [x] Controlled reader, passive definition extraction and explicit coverage reporting.
